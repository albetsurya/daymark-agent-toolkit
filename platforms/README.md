# Platform Packaging Notes

The package generator should create these directories from canonical MCP server metadata and shared Skills. Never hand-maintain different copies of tool schemas.

```text
dist/platforms/
  claude-code/
    .claude-plugin/plugin.json
    .mcp.json
    skills/...
  codex/
    .codex-plugin/plugin.json
    .mcp.json or documented MCP config reference
    skills/...
  cursor-agent-plugin/
    plugin.json
    mcp.json
    skills/...
  cursor-native/            # optional richer Cursor-only features
    .cursor-plugin/plugin.json
    rules/...
    hooks/...
    skills/...
  antigravity/
    .antigravity-plugin/plugin.json
    mcp_config.json
    hooks.json              # only if opt-in native hooks are added
    skills/...
  opencode/
    opencode.json or setup snippet for MCP
    .opencode/skills/...
```

This is a target output plan, not a promise every file is already valid. The generator must follow the latest official schema for each target and validate the result. Prefer local absolute executable paths in generated local configs only when the installer can determine them safely; otherwise use documented package execution commands and environment variables.

## Implementation notes (2026-11-26)

- Generated by `pnpm pack:platforms` (portable mode, `daymark-mcp` command) or `pnpm --filter @daymark/platform-adapters exec node dist/bin.mjs pack --local` (local dev mode pointing to `packages/mcp-server/dist/bin.mjs`).
- Packaged skill directories inside `dist/platforms/<target>/skills/` (and `.opencode/skills/`) use the frontmatter `name` (`daymark-daily-planning`, `daymark-daily-wrap`, `daymark-task-triage`) as folder name to satisfy `agy plugin validate --strict` and OpenCode skill discovery without modifying the canonical `skills/` source layout.
- OpenCode `opencode.json` emits `mcp.servers.daymark` matching the format produced by `opencode mcp add` (`opencode v2.2.5`) and parsed by `opencode debug config`.
