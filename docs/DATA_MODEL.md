# Data Model (MVP)

All primary IDs are UUID strings generated by the application. All persisted instants are ISO-8601 UTC strings or integer epoch milliseconds; choose one representation consistently and document it in the migration. Prefer integer epoch milliseconds for calculations and ISO strings at API boundaries.

## Tables

### `projects`

- `id` TEXT PRIMARY KEY
- `name` TEXT NOT NULL
- `description` TEXT NULL
- `status` TEXT NOT NULL CHECK (`active`, `archived`)
- `created_at`, `updated_at` INTEGER NOT NULL
- `archived_at` INTEGER NULL

### `tasks`

- `id` TEXT PRIMARY KEY
- `title` TEXT NOT NULL, trimmed, 1–240 chars
- `description` TEXT NULL
- `project_id` TEXT NULL REFERENCES `projects(id)` ON DELETE SET NULL
- `status` TEXT NOT NULL CHECK (`inbox`, `todo`, `in_progress`, `completed`, `cancelled`, `archived`)
- `priority` TEXT NOT NULL CHECK (`none`, `low`, `medium`, `high`)
- `estimate_minutes` INTEGER NULL CHECK > 0 and <= 10080
- `due_at` INTEGER NULL
- `completed_at` INTEGER NULL
- `created_at`, `updated_at` INTEGER NOT NULL
- `source_agent` TEXT NOT NULL DEFAULT `unknown`
- `external_ref` TEXT NULL (reserved for future integrations; no remote sync in MVP)

Indexes: `(status, priority)`, `due_at`, `project_id`, `(updated_at)`.

### `tags` and `task_tags`

`tags`: `id` TEXT PRIMARY KEY, `name` TEXT NOT NULL UNIQUE, `created_at` INTEGER NOT NULL.

`task_tags`: `task_id` TEXT NOT NULL REFERENCES `tasks(id)` ON DELETE CASCADE, `tag_id` TEXT NOT NULL REFERENCES `tags(id)` ON DELETE CASCADE, PRIMARY KEY (`task_id`, `tag_id`).

### `focus_sessions`

- `id` TEXT PRIMARY KEY
- `task_id` TEXT NULL REFERENCES `tasks(id)` ON DELETE SET NULL
- `project_id` TEXT NULL REFERENCES `projects(id)` ON DELETE SET NULL
- `status` TEXT NOT NULL CHECK (`active`, `completed`, `interrupted`)
- `started_at` INTEGER NOT NULL
- `ended_at` INTEGER NULL
- `duration_seconds` INTEGER NULL, calculated on finish
- `note` TEXT NULL
- `source_agent` TEXT NOT NULL DEFAULT `unknown`
- `created_at`, `updated_at` INTEGER NOT NULL

MVP invariant: allow at most one active focus session per profile. Enforce transactionally; add a partial unique index if supported by the selected SQLite version.

### `worklog_entries`

- `id` TEXT PRIMARY KEY
- `task_id` TEXT NULL REFERENCES `tasks(id)` ON DELETE SET NULL
- `project_id` TEXT NULL REFERENCES `projects(id)` ON DELETE SET NULL
- `focus_session_id` TEXT NULL REFERENCES `focus_sessions(id)` ON DELETE SET NULL
- `summary` TEXT NOT NULL, trimmed, 1–2000 chars
- `details` TEXT NULL
- `duration_minutes` INTEGER NULL CHECK >= 0 and <= 1440
- `occurred_at` INTEGER NOT NULL
- `source_agent` TEXT NOT NULL DEFAULT `unknown`
- `created_at` INTEGER NOT NULL

### `settings`

- `key` TEXT PRIMARY KEY
- `value_json` TEXT NOT NULL
- `updated_at` INTEGER NOT NULL

Required settings: `timezone` (IANA name), `week_starts_on`, `day_start_time` (display preference only), `default_plan_minutes` (optional).

### `idempotency_records`

- `scope` TEXT NOT NULL (for example `capture_task` or `log_work`)
- `idempotency_key` TEXT NOT NULL
- `resource_id` TEXT NOT NULL
- `created_at` INTEGER NOT NULL
- `expires_at` INTEGER NULL
- PRIMARY KEY (`scope`, `idempotency_key`)

This table prevents duplicate write operations when a client retries after a timeout.

### `schema_migrations`

- `version` TEXT PRIMARY KEY
- `applied_at` INTEGER NOT NULL

## Relationships and deletion

- Deleting a project must not delete tasks/worklogs; set `project_id` null or prefer archive.
- Tasks are archived, not permanently deleted, through normal UX.
- Permanent deletion, if later implemented, must be explicit and audited.
- A focus session may outlive task archival; it must remain queryable.
- Backup/restore must preserve IDs and relationships.

## Future tables (do not create in MVP unless needed)

`notes`, `agent_sessions`, `audit_events`, `integrations`, `calendar_events`, `goals`, `recurrence_rules`, `sync_outbox`.

## Time handling

- Store instants in UTC.
- Interpret dates and week boundaries using the configured IANA timezone.
- Do not treat a date-only deadline as midnight UTC. Use a documented local end-of-day policy or preserve a date-only type; the implementation should choose one and test it.
- Inject a clock into domain use cases for deterministic tests.
